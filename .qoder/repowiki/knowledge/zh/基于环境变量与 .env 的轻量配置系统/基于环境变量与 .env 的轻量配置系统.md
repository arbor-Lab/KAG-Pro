## 1. 采用的方式
- 使用 `python-dotenv` 加载项目根目录下的 `.env` 文件，并通过 `os.getenv` 读取运行时参数。
- 所有配置项集中在 `src/kag_pro/utils/config.py` 中，通过 `get_config()` 返回一个扁平字典，供各模块按需取用。
- 依赖声明、可选功能开关（如本地 embedding、faiss）通过 `pyproject.toml` 的 `[project.optional-dependencies]` 管理。

## 2. 关键文件与包
- `src/kag_pro/utils/config.py`：唯一官方配置入口，负责加载 `.env` 并暴露 `get_config()`、`get_project_root()`。
- `.env.example`：提供完整的环境变量模板，说明每个键的作用与默认值。
- `pyproject.toml`：声明核心依赖与可选依赖（`local-embed`、`faiss`、`dev`、`all`），作为“安装级”配置来源。
- 消费方示例：
  - `src/kag_pro/core/embedder.py`：从 `get_config()` 取 `embedding_model`、`embedding_base_url`、`embedding_api_key` 等。
  - `src/kag_pro/core/generator.py`：取 `openai_api_key`、`openai_base_url`、`dashscope_api_key`、`llm_model`。
  - `src/kag_pro/core/retriever.py`：取 `retrieval_top_k`、`retrieval_threshold`。
  - `src/kag_pro/core/vector_store.py`：取 `chroma_persist_dir` 并配合 `get_project_root()` 定位持久化目录。

## 3. 架构与约定
- **单一数据源**：`.env` 是运行时配置的唯一来源；`get_config()` 在模块首次 import 时即加载一次，后续调用直接读内存 dict。
- **扁平键空间**：所有配置以字符串键形式暴露，类型转换（`int`/`float`）在 `get_config()` 内完成，避免在各业务模块重复解析。
- **分层默认值**：对必填项（如 API Key）使用空串默认值，由上层调用处校验；对可选项（如 `LLM_MODEL`、`CHROMA_PERSIST_DIR`）给出合理默认值，保证开箱即用。
- **路径解析策略**：`get_project_root()` 基于当前文件路径向上推导项目根目录，再拼接相对路径（如 `data/chroma_db`），使配置值保持环境无关的相对路径风格。
- **可选能力开关**：通过 `pip install kag-pro[local-embed,faiss]` 选择启用本地 embedding 或 faiss 后端，属于“安装期配置”，不在运行时 env 中切换。

## 4. 开发者应遵循的规则
1. **新增配置项**：统一在 `src/kag_pro/utils/config.py::get_config()` 中添加键与默认值，并在 `.env.example` 中同步注释说明。
2. **取值方式**：其他模块一律通过 `from kag_pro.utils.config import get_config; config = get_config()` 获取，禁止直接 `os.getenv` 散落各处。
3. **类型安全**：需要数值类型的字段在 `get_config()` 中做 `int()`/`float()` 转换，调用方直接使用 Python 原生类型。
4. **敏感信息**：API Key 等敏感字段仅放在 `.env` 中，不要硬编码进代码；`.env` 已在 `.gitignore` 中排除版本控制。
5. **路径配置**：涉及文件系统的路径（如 `CHROMA_PERSIST_DIR`）使用相对于项目根的相对路径，由 `get_project_root()` 拼接绝对路径。
6. **可选依赖**：如需引入新后端（如新的向量库），优先通过 `pyproject.toml` 的 optional-dependencies 声明，并在导入处做 try/except 降级处理。
